# Phase 5: Release 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release 1.0.0. The program is reviewed for security as a whole, operated from one guide that is proven by a deployment made from it, and frozen under the rules of spec 15.1, then tagged after the gate.

**Architecture:** Four fixes come first, so the review reads the code that ships: the PDF attempt guard (F-123), `admin reset-password` (F-148), a fixed Compose subnet so a host proxy can be trusted (F-147), and a `make audit` target running three scanners. Eight reviewers then read the program at one commit, area by area. Every claim is proven live or by a failing test before it is ruled, and the blocking ones are fixed. Two documents follow: `docs/security.md` and `docs/operations.md`. Two tests hold the guide's tables equal to the code, and the guide is walked word for word on a fresh deployment behind Caddy. Last, a test pins the released migrations, and the version, the gate, and the owner's word close the phase.

**Tech Stack:** As in part 4.6. New in the devShell: `govulncheck` 1.8.0 and `trivy` 0.74.0 from the pinned nixpkgs (R274). Caddy 2 is used only by the walk, as a container, and never enters the repository's Compose files.

**Spec:** `docs/superpowers/specs/2026-09-27-k8s-capacity-report-design.md` as amended in `a534c05` (approved by the owner on 2026-10-10): 11.3 (`admin reset-password`), 11.7 (the render claim), 15.1 (from 1.0.0 on), 16 and 16.1 (release 1.0.0). The owner's answers are in `ROADMAP.md`, "Decisions of the owner", row of 2026-10-10.

**Depends on:** `main` at `3786989`. Branch `release/1.0.0`, which holds the spec amendment `a534c05`.

## Global Constraints

Every constraint of the plans of phases 0 to 4.6 stands, and `AGENTS.md` binds every task. The ones this phase leans on most:

- **Every command runs inside `nix develop`** from the repository root. The host is NixOS: only `/bin/sh` and `/usr/bin/env` exist under `/bin` and `/usr/bin`.
- **A subagent never runs Docker.** `make image`, `make e2e`, `make gate`, `make audit`, `make postgres-up`, and the walk belong to the main thread. A subagent may run `go`, `make build`, `make test`, `make lint`, `make web`, `make generate`, `make generate-check`, and `npm` inside `web/`, and runs tagged tests with `KCR_TEST_DATABASE_DSN=postgres://kcr_test:kcr_test_only@127.0.0.1:55432/kcr_test?sslmode=disable` once the main thread has started PostgreSQL.
- **No test skips.** A tagged test fails when its tool or its database is missing.
- **Diagnostics are English;** reader text of the report lives in the catalog. This phase adds no catalog entry and no locale key.
- **No message repeats an argument that was not understood.**
- **Every failure of a command prints one line,** `error: <message>`, on standard error. `admin` exits 0, 1 (run time, a refusal), or 2 (arguments, settings file).
- **Every timestamp is passed from Go;** no statement calls `now()`.
- **The stored data is junk until the tag** (spec 15.1). The migrations are edited in place until Task 12 pins them, and never after.
- **Comments say what the code does.** None names a task, step, ruling, brief, finding, or `.cache/` path.
- **Commits:** `type(scope): description`, imperative, under 50 characters (each subject below is counted). Stage with `git add <paths>`; never `-A`, never `commit -a`; never stash, restore, check out a path, or clean.
- Scratch goes under `.cache/phase-5/`.

## Review Focus

Each line names a condition the spec implies and no requirement spells out, and the test that pins it.

1. **A render attempt that wakes after River rescued its job,** with the newer attempt still running or already done. A reasonable person expects the newer outcome to stand. Pinned in Task 1 by `TestRenderRescuedAttemptWritesNothing` and `TestRenderRescuedFailureWritesNothing`, which hold the row at a later attempt before the outcome is written.
2. **An old render job that wakes after its failed PDF was requested again.** The row now carries a new `job_id`, and the old job must not finish the new request. Pinned in Task 1 by `TestRenderOfAReplacedJobWritesNothing`.
3. **A reset of a user who is signed in elsewhere,** or who is deactivated. A reasonable person expects every open session to end, and a deactivated account to stay closed. Pinned in Task 2 by `TestResetPasswordRevokesSessions` and `TestResetPasswordRefusesAnInactiveUser`.
4. **A host proxy whose `trusted_proxies` does not name the address `serve` sees.** A reasonable person expects that one attacker cannot block a named user's sign-in for everyone. Pinned in Task 11 by the walk's two-client throttle check, seen failing with `trusted_proxies = []`.
5. **A guide step that works only because of the author's machine:** an image already built, a variable left exported, a volume left over, a tool on the host. Pinned in Task 11: the walk runs from `env -i` in a fresh folder, after `docker compose down --volumes` of the project, and every command it runs is copied from the guide's text by a script, not typed.

## How to read this plan

As in parts 4.2 to 4.6, each task gives exact paths, interfaces, SQL, and the assertions of each test. The Go changes are written test first.

Executors:
- **Subagent:** a Sonnet subagent in the main checkout, no worktree. It writes the change, runs the tests its brief names, and runs `make test` and `make lint`. It never runs Docker and cannot declare a task finished.
- **Reviewer:** a Sonnet `adversarial-reviewer` reading a diff file. It runs tests only on packages that nobody is editing, and writes its findings to a report file under `.cache/phase-5/` and to its final message.
- **Main thread:** the threat model, the judgment of every claim, the prose of both documents, every Docker step, `AGENTS.md`, and the owner.

Rules for every brief:
- Tasks run in sequence. Tasks 1 and 2 share no package and may run in parallel; every other pair runs in order.
- The brief appends this plan's rulings for its task, the Global Constraints, and the Review Focus rows its task owns.
- Before a Docker step: `systemctl is-active docker` prints `active`, `docker context show` prints `default`, `docker info --format '{{.OperatingSystem}}'` starts with `NixOS`, and port 8080 is free. Long runs go to background tasks with logs under `.cache/phase-5/`.

**Order:** Task 0 → (Task 1 ∥ Task 2) → Task 3 → Task 4 → Task 5 → Task 6 → Task 7 → Task 8 → Task 9 → Task 10 → Task 11 → Task 12 → Task 13.

```go
// ClaimPDF gives the pending PDF row of a report's language to one attempt of
// its render job. It refuses another job and an older attempt with
// ErrStaleAttempt.
func ClaimPDF(ctx context.Context, tx pgx.Tx, reportID uuid.UUID, language string, jobID int64, attempt int, now time.Time) error

func FinishPDF(ctx context.Context, q Querier, reportID uuid.UUID, language string, jobID int64, attempt int, body []byte, now time.Time) error
func FailPDF(ctx context.Context, q Querier, reportID uuid.UUID, language string, jobID int64, attempt int, code string, now time.Time) error
```

  The SQL, each run through `execGuarded` (`reports.go:163`), which gives `ErrStaleAttempt` when no row changed:

```sql
-- ClaimPDF
UPDATE report_pdfs SET attempt = $4, updated_at = $5
WHERE report_id = $1 AND language = $2 AND status = 'pending' AND job_id = $3 AND attempt <= $4
-- FinishPDF
UPDATE report_pdfs SET status = 'ready', body = $5, sha256 = $6, size_bytes = $7, updated_at = $8
WHERE report_id = $1 AND language = $2 AND status = 'pending' AND job_id = $3 AND attempt = $4
-- FailPDF
UPDATE report_pdfs SET status = 'failed', failure_code = $5, updated_at = $6
WHERE report_id = $1 AND language = $2 AND status = 'pending' AND job_id = $3 AND attempt = $4
-- RetryPDF (signature unchanged)
UPDATE report_pdfs SET status = 'pending', failure_code = NULL, job_id = $3, attempt = 0, updated_at = $4
WHERE report_id = $1 AND language = $2 AND status = 'failed'
```
