# Phase 12: the rename to CapacityRoom

Date: 2026-10-14. Status: approved in conversation by the owner, written for review.

## Purpose

The project takes one name before it is deployed on Kubernetes (phase 13) and
released to the public (phase 14). The product is CapacityRoom. Today only the
web app carries that name; the command, the Go module, the images, the
environment variables, and the deploy files carry `k8s-capacity-report` or
`kcr`. After this phase, every live name is CapacityRoom or one of its fixed
technical forms, and nothing new is named after the old one.

The phase changes names only. No behaviour, no number, no query, no schema,
and no layout changes, except the one sentence of the PDF that names the
program.

## Decisions of the owner (2026-10-14)

- The full rename comes first, as phase 12. The Kubernetes deployment is
  phase 13 and the public release phase 14.
- Environment variables take the prefix `CAPACITYROOM_`; lowercase identifiers
  take `capacityroom_` or `capacityroom-`.
- The colophon of the PDF names the product, CapacityRoom, in both languages.
- No Compose stack holds reports worth keeping: the Compose project, volume,
  database, user, and configuration mount are renamed with no upgrade path,
  and the changelog says so (option B).
- The images are `capacity-room` everywhere; the Docker Hub repository is
  `alvesmarcelocf/capacity-room`, private, created by the owner (used in
  phase 13).
- The GitHub repository and the local folder are both renamed at the end of
  the phase. The owner moves the folder.
- The hash domain of a profile fingerprint is renamed too, accepting one new
  revision per profile at its next revise or import.

### What does not change

- The PostgreSQL advisory lock numbers `72427301` and `72427302`, River, the
  schema, and every migration. A released migration is never edited.
- The snapshot file and its `schema_version` 2.0. A snapshot does not name the
  program, so every stored and golden snapshot stays byte for byte.
- The Typst package `graphite-report` and its public surface.
- The names of the original program (`kubernetes-report`,
  `kube_capacity_report`) wherever the documents cite it.
- The fingerprints stored before 2.0.0 are not recomputed. A profile revised or imported again after the upgrade writes one new revision even when its document is unchanged, since its fingerprint now differs from the stored one; that is the owner's ruling of 2026-10-14.
- The file names `report.toml`, `platform.toml`, `profiles.toml`, and the
  keys inside them.
- The recorded answers of `testdata/prometheus/` and the records of
  `testdata/python/`.

### Living documents and history

Living documents are rewritten to the new names: `README.md`, `AGENTS.md`,
`docs/operations.md`, `docs/security.md`, `DESIGN.md`, `PRODUCT.md`, and the
text of the design `docs/superpowers/specs/2026-09-27-k8s-capacity-report-design.md`,
which keeps its dated file name so that every reference to it stays valid.

History stays as written: the plans under `docs/superpowers/plans/`, the
specs other than the design, `docs/decisions/`, `docs/reference/`, and the
changelog entries of the 1.x versions and earlier.

AGENTS.md's rule "The web app is named CapacityRoom; nothing outside `web/`
and the documents takes that name" is replaced by: "The product is
CapacityRoom. The command, the Go module, the images, and the deploy names
are `capacity-room`; environment variables start with `CAPACITYROOM_`; a
lowercase identifier starts with `capacityroom_` or `capacityroom-`." Every
command, path, and variable that AGENTS.md cites moves to the new name.

## The guard of the old name

A new guard in `internal/guard` reads every tracked file and refuses the old
names: `k8s-capacity-report`, `KCR_` at a word start, and `kcr` as a word or
followed by `_` or `-`, case-insensitively. It skips:

- `docs/superpowers/plans/`, every file of `docs/superpowers/specs/` except
  the design, `docs/decisions/`, and `docs/reference/`;
- `testdata/python/` and `testdata/prometheus/`;
- in `CHANGELOG.md`, every line under a version heading below 2.0.0;
- the files of the guard itself, which hold the patterns.

A refusal names the file and the line. The guard joins `make test`, and it is
seen failing before the phase closes: a mutation that puts one `KCR_` back
into a live file makes it fail, and the run is recorded.

The list of skipped paths is a closed list in the guard. A new history path
enters it by an edit that a reviewer reads.

## Execution

Branch `refactor/capacity-room`, cut from `main` at `b59bbb6`. The tasks share
files, so they run in sequence, each with a fresh Sonnet implementer and a
task reviewer, briefs and reports as files, and the ledger under
`.superpowers/sdd/2026-10-14-phase-12-rename/`.

1. **Module, command, and images.** The module path in `go.mod` and every
   import, `cmd/capacity-room/`, the `Makefile` targets and image tags, the
   two Containerfiles, the image names and the project of the Compose files,
   the temporary prefixes, the cobra `Use`, and the `--version` line with its
   check in the `Makefile`. Done when `make build`, `make test`, and
   `make lint` pass.
2. **Environment and identifiers.** Every `KCR_` becomes `CAPACITYROOM_`, in
   the Go code, the tests, the `Makefile`, the Compose files, the e2e specs,
   and the web scaffolding. The cookies, the meta of `index.html` with its Go
   test, the test database prefix, the Compose database, user, and mount, and
   `deploy/platform/`. `make generate` runs if the contract changes. Done when
   `make test` and `make lint` pass; the main thread then runs
   `make test-postgres`.
3. **The colophon.** The main thread writes the two catalog entries and the
   negative fixture `template/tests/capacity/negative/misplaced-colophon.json`.
   Then `make update-testdata`, `go test ./...` and the web suite before the
   data is committed, then `make update-golden` on the main thread. Every
   changed page is opened; the colophon line is the one expected difference.
4. **Documents.** The living documents of the section above, the title of
   `api/openapi.yaml` with `make generate` and `make generate-check`, and
   `flake.nix`. The tests that hold `docs/operations.md` equal to the code
   pass.
5. **The guard.** It is written, seen failing on a mutation, and passes on the
   branch.

Then `make gate` over the combined branch, read by its own summary line, and
an adversarial review of the whole branch with one fix wave. The review hunts
in particular for an old name that the guard's patterns miss, such as
`K8sCapacityReport` or `kcr` joined to another word, and for a renamed
identifier that a test still expects under its old name.

## Version and changelog

The command name and the environment variables are public surface under
spec 15.1, so the release is 2.0.0, by the short flow: a version commit on the
branch touching `VERSION`, the changelog heading, and the three graphite-report
version spots (`template/graphite/README.md`,
`template/graphite/template/main.typ`, `template/graphite/typst.toml`); then
`make gate` and `make audit` on that commit, `main` fast-forwarded, and the
annotated tag `v2.0.0`, its logs kept under `.cache/release-2.0.0/`.

The changelog of 2.0.0 holds:

- **Changed:** the command is `capacity-room`; every environment variable
  starts with `CAPACITYROOM_`; the PDF names CapacityRoom in its last line;
  the Compose project, its database, and its configuration folder take the
  new name.
- **Removed:** reports stored by a Compose stack before 2.0.0 are not carried
  forward, since the new stack starts with a new volume; every signed-in
  session ends at the upgrade; a theme or a language chosen before sign-in
  is forgotten once.

The internal work (the guard, the renamed test scaffolding, the images of the
tests) is left out, and the report of the phase says so.

## Definition of done

- No tracked file outside the skipped history holds an old name, and the guard
  proves it on every `make test`, having been seen failing.
- `make gate` passes on the version commit, and `make audit` passes.
- The golden pages differ from 1.6.0 by the colophon line alone, each changed
  page opened and reviewed.
- The adversarial review's findings are fixed or ruled, and recorded in
  `ROADMAP.md`.
- `ROADMAP.md` and `CHANGELOG.md` are read back after their update.
- On the owner's word: the tag `v2.0.0`, the GitHub repository renamed, and
  `main` and `v2.0.0` pushed to the new remote.
